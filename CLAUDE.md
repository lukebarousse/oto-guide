# OTO Guide — instructions for AI assistants

Multi-team race guide for the Outback in the Ozarks relay. Static pages (generated by Python) + Supabase for team data and admin-edited leg content. Two race variants share one codebase: **205** (all 36 legs, starts Friday, Lake Leatherwood) and **65** (legs 25–36 rebased to mile 0, starts Saturday, Lake Fort Smith, orange accent).

## Build (after ANY change to builder/*)

```bash
cd builder
../.venv/bin/python build.py                                  # 205 -> out/
OTO_DATA=data65 OTO_OUT=out65 ../.venv/bin/python build.py    # 65  -> out65/
cp out/*.html .. && cp out65/*.html ../65/
```

Never edit the root/65 HTML directly — always regenerate. `data65.py` derives from `data.py` (filter + mile rebase); race-specific knobs are module attrs read via `getattr` in build.py (RACE_ID, RACE_DAYS, START_KEY/LABEL, ACCENT, JS_PREFIX, PLAN_NOTE).

## Architecture

- `builder/data.py` — all 36 legs' content (beta/tags/ratings/surface), race facts, PLAN defaults. This seeds the DB (`supabase/seed_legs.sql` is generated from it) but at runtime the **database wins**: `js/team.js` overlays season leg content and team config onto the static pages.
- `js/team.js` — runtime overlay. No config or no `?team=` → pages stay static. With a team slug: rebrands, applies roster + per-leg assignments (data-slot patching), rebuilds filters/planner, applies team pace/wave to the timeline, bounces to `/65/` if the team is a 65-mile team.
- `settings.html?team=<slug>` — captain-facing editor (roster, size, pace, leg-by-leg assignment grid). Writes via anon key; capability-URL security model (deliberate).
- `admin.html` — Supabase Auth (signups disabled; admins created by hand). Seasons (create/activate, legs content copied forward), teams (create with race 205/65 + duplicate from any season's team, wave assignment, projected finish for wave planning), per-leg content editor.
- `404.html` — GitHub Pages shim: `/t/<slug>` → `index.html?team=<slug>`.
- `supabase/schema.sql` — tables seasons/teams/runners/assignments/legs + RLS: public read everywhere, public write on team-scoped tables, authenticated-only on seasons/legs/team-create-delete.

## Conventions & gotchas

- Leg numbering is official (65-mile legs are 25–36, never renumbered). `assignments` maps leg → slot; default is rotation `(index % n_runners) + 1`.
- Exchange coordinates: `builder/starts.json`, key k = start of leg k+1 (0 = start line, 36 = finish). From the race's official Google My Maps.
- The anon key in `js/config.js` is public by design; the service-role key must never appear in this repo.
- Test JS via `python3 -m http.server` (not file://). Static mode must never throw — guard all DB code on `OTO_CONFIG.url`.
- After changing `data.py` leg content, regenerate `supabase/seed_legs.sql` (script pattern in git history) so fresh DB installs match.
